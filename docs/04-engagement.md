## 0. 이 문서의 전제

일반적인 할일 앱의 리텐션 설계는 **보상**에서 출발한다. 스트릭, 포인트, 레벨, 뱃지.

이 앱은 다르게 간다. Phase 3에서 이탈 원인 1순위가 나왔기 때문이다.

> **S5-b: "적는 게 귀찮아짐 — 다른 데 적는 게 더 빠름"**

성취감이 부족해서 떠나는 게 아니다. **적는 데 5초가 걸려서** 떠난다.
보상을 아무리 쌓아도 입력이 느리면 카톡으로 간다.

그래서 이 문서의 무게중심은 이렇다.

```
마찰 제거  ████████████  (E1, E2)
즐거움     ██████        (E3, E4)
회복       ████          (E5)
보상       —             의도적으로 비움 (5장)
```

**채택**: A1 · A3 · B4 · C1 · D1 → E1~E5

## E1. 한 줄 추가 바 ⭐

> 3탭을 **1탭**으로. 이 앱에서 가장 중요한 장치.

### 근거

- **S1** (회의 후 걸으며, 한 손, 10초) — 최악 조건 입력
- **S9** (역시나리오) — "1일차 12초 → 3일차 카톡으로" 경로를 끊는 지점
- **P1** (입력은 3탭·3초)

### 동작

```
평상시 (하단 고정)
┌─────────────────────────────┐
│  8월 3일 (오늘)              │
│  ▢ 주간보고 초안      직장   │
│  ▢ 어린이집 준비물    가족   │
│                             │
├─────────────────────────────┤
│ ✎ 할일 추가…            [⋯] │  ← 하단 고정 바
└─────────────────────────────┘

탭 하면
┌─────────────────────────────┐
│ [직장] [개인] ●가족  [+]     │  ← 카테고리 칩. 마지막 사용이 선택됨
│ ✎ 어린이집 준비물_      [⋯] │
└─────────────────────────────┘
        ↑ 키보드
```

| 항목 | 규칙 |
|---|---|
| 저장 | **Enter 한 번.** 저장 버튼을 누르러 갈 필요 없음 |
| 저장 후 | 입력창이 **닫히지 않는다.** 커서 유지 → 연속 입력 가능 |
| 날짜 | **현재 선택된 날짜** (P6). 오늘을 보면 오늘, 내일을 보면 내일 |
| 카테고리 | 마지막 사용 카테고리가 선택된 상태. 바꾸려면 칩 1탭 |
| 기간·매일체크 | `[⋯]` 를 눌러 상세 모달로. **기본 경로에서는 보이지 않음** (P5) |
| 위치 | 하단 고정 — 엄지 도달 범위 (P4) |

### 엣지 케이스

- **한글 IME**: 조합 중 Enter가 중복 저장을 일으키면 안 된다. `isComposing` 확인 필수 (요구사항 6.4). **이 장치의 성패가 여기 달렸다**
- **빈 입력 Enter**: 아무 일도 일어나지 않는다. 에러 메시지도 띄우지 않는다
- **키보드가 리스트를 가림**: 입력 바는 키보드 위에 붙고, 리스트는 그만큼 스크롤 여유를 갖는다
- **카테고리가 0개**: 칩 영역에 `[+ 카테고리 만들기]` 만 표시
- **오프라인**: 낙관적 반영 + 큐 적재 (요구사항 3.5). 입력 경험은 온라인과 **동일**

### 기존 [+] 버튼과의 관계

한 줄 추가 바가 **[+]를 대체한다.** 둘 다 두면 하단이 복잡해진다.
상세 입력(기간·매일체크·메모)은 `[⋯]` 하나로 접근한다.

### 검증 기준

- 앱 실행 → 할일 저장까지 **3초 이내, 탭 2회 이내**(입력 바 탭 + Enter)
- 연속으로 3개를 적을 때 중간에 화면 전환이 없다

## E2. PWA 홈 화면 설치

> 앱을 여는 경로 자체를 줄인다.

### 근거

- **S7** (카톡 → 앱 왕복) — 전환 비용이 이탈의 시작
- **S9** — "3일차: 그냥 카톡에 보내자"
- **S8** (서지호) — 데모용으로도 인상이 좋다

### 동작

| 항목 | 내용 |
|---|---|
| manifest | 이름 · 아이콘(192/512) · `display: standalone` · 테마 색 |
| 실행 화면 | 브라우저 주소창·탭바 없이 **전체 화면** |
| 설치 유도 | **자동 팝업을 띄우지 않는다.** 설정 화면에 조용한 안내 한 줄만 |
| 오프라인 | Service Worker로 앱 셸 캐시 → 비행기 모드에서도 실행됨 |

### 요구사항 3.5와의 관계

오프라인 데이터 캐시는 이미 결정됐다(3.5). PWA는 **앱 셸(HTML/JS/CSS) 캐시**를 더해
"오프라인에서 열리기까지" 완성한다. 둘이 합쳐져야 S2(지하철)가 완전히 성립한다.

### 하지 않는 것

- 설치 유도 배너·모달 (P12의 정신 — 방문자를 붙잡지 않는다)
- 푸시 알림 권한 요청 (5장에서 금지)

## E3. 체크 마이크로 인터랙션

> 0.25초. 이 앱에서 유일하게 "화려한" 부분.

### 근거

- **S8 20초 지점** — 서지호가 체크를 눌러보는 순간이 **가장 강한 데모**
- **S6** — 하루 끝의 성취감이 시각적으로 남음
- **P11** — 즉각 반응

### 동작

```
체크 전                        체크 후 (0.25초)
┌──────────────────────┐      ┌──────────────────────┐
│ ▢ 주간보고 초안  직장 │  →   │ ☑ ̶주̶간̶보̶고̶ ̶초̶안̶  직장 │
│   (연한 파랑 배경)    │      │   (색이 번지며 옅어짐) │
└──────────────────────┘      └──────────────────────┘
        동시에
   달력의 해당 점도 옅어짐  ← 인과관계를 눈으로 전달
```

| 항목 | 규칙 |
|---|---|
| 시간 | 200~300ms. 그 이상은 매일 쓰는 사람에게 방해 |
| 내용 | 체크 표시 + 카테고리 색이 카드에 번짐 + 취소선 |
| 동시 반영 | **달력의 점이 같은 타이밍에 변한다.** 이게 핵심 — "여기가 저기에 연결돼 있구나" |
| 해제 | 되돌리는 애니메이션도 동일하게. 실수로 눌렀을 때 부담 없어야 함 |
| 접근성 | `prefers-reduced-motion` 을 존중해 애니메이션 제거 |
| 오프라인 | 서버 응답과 무관하게 **즉시** 재생 (낙관적 반영) |

### 검증 기준

- 체크 → 달력 반영 사이에 **인지 가능한 지연이 없다**
- `prefers-reduced-motion: reduce` 에서 애니메이션 없이 상태만 바뀐다

## E4. 엄선 파스텔 팔레트 ⭐

> 색 고르기가 이 앱의 즐거움이다. 기능이 아니라 콘텐츠.

### 근거

- **S4-c** (자주 손댐 — 색 바꾸는 재미로)
- **S5** (퇴근길, 목적 없이 앱을 만짐) — 목적 없이 여는 이유
- **P8, P9**

### 동작

| 항목 | 규칙 |
|---|---|
| 색 개수 | **12색.** 8개는 적고 20개는 고르기 피곤하다 |
| 자유 컬러피커 | **제공하지 않는다.** 선택 부담이 늘고 못생긴 색이 나온다 (P9) |
| 미리보기 | 색을 탭하는 **즉시** 카드와 달력에 반영. 저장 버튼을 기다리지 않음 |
| 되돌리기 | 편집을 취소하면 원래 색으로 복귀 |
| 접근 경로 | **2탭 이내.** 카테고리 칩 길게 누르기 → 편집, 또는 상단 카테고리 영역에서 바로 |
| 중복 | 이미 쓰는 색도 고를 수 있다. 단 **아직 안 쓴 색을 먼저** 보여준다 |
| 새 카테고리 | 미사용 색 중 하나를 자동 배정 (고르지 않아도 예쁘게 시작) |

### 색 자체의 조건

파스텔은 예쁘지만 **접근성에서 불리하다.** 채도가 낮아 색끼리 구분이 안 되고, 텍스트 대비가 떨어진다.

```
카드 배경  : 파스텔 (매우 옅게)     ← 눈에 편안
카드 텍스트: 같은 색상의 어두운 톤   ← WCAG AA 4.5:1 확보
달력 점    : 같은 색상의 진한 톤     ← 작아도 보이게
```

**한 카테고리 색 = 3단계 톤 세트**로 정의한다. 실제 hex 값은 Phase 5에서 확정.

### 안전장치

색만으로 구분하지 않는다는 원칙(요구사항 6.2)은 그대로다.
카드에는 **카테고리 이름 텍스트가 항상** 함께 있다. 팔레트가 예뻐도 이 규칙은 안 바꾼다.

## E5. 밀린 할일 이월

> 못 한 걸 없던 일로 만들지 않되, 죄책감의 벽도 만들지 않는다.

### 근거

- **S9 1일차~14일차** — "며칠 못 열었더니 밀린 게 잔뜩"
- **S6** (하루 마감) — 못 한 걸 내일로 미루는 행위

### 동작

```
┌─────────────────────────────┐
│  2026년 8월     [달력]       │
├─────────────────────────────┤
│  ⌄ 밀린 할일 3               │  ← 접혀 있음. 탭하면 펼쳐짐
│    ▢ 세탁소 맡기기  가족 7/28│
│      └ [오늘로]              │  ← 1탭 이동
│    ▢ 보고서 검토   직장 7/30 │
├─────────────────────────────┤
│  8월 3일 (오늘)              │
│  ▢ 주간보고 초안      직장   │
└─────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 대상 | **오늘 이전**에 끝났어야 하는 미완료 할일 (`endDate < 오늘 && !done`) |
| 표시 위치 | 오늘 리스트 **위**. 단 **오늘을 보고 있을 때만** |
| 기본 상태 | **접혀 있다.** 개수만 보임. 펼치는 건 선택 |
| 날짜 변경 | **자동으로 바꾸지 않는다.** 원본 날짜를 그대로 유지하고 표시만 끌어옴 |
| 오늘로 옮기기 | 항목별 1탭. 이때만 `endDate`가 바뀐다 |
| 지속형 제외 | `checkMode: 'daily'` 는 이월 대상이 아니다. 매일 뜨는 것에 "밀림"은 성립하지 않음 |
| 많이 쌓이면 | 접힌 상태 그대로 `밀린 할일 27` 로만. 펼치기 전엔 압박이 없음 |

### 왜 자동으로 날짜를 안 바꾸나

자동 이월은 **기록을 왜곡한다.** 7/28에 못 한 일이 8/3 것으로 바뀌면,
"내가 그때 뭘 못 했는가"가 사라진다. 표시만 끌어오고 데이터는 그대로 두는 게 맞다.

### 왜 기본이 접힘인가

밀린 게 12개인 채로 앱을 열었을 때, 그게 화면을 채우면 **앱을 닫게 된다.**
S9의 이탈 경로가 정확히 그것이다. 개수만 보이고, 볼지 말지는 사용자가 정한다.

## 2. 의도적으로 넣지 않는 것

넣지 않는 이유를 남겨두지 않으면, 구현 중에 "이거 있으면 좋겠는데"로 슬금슬금 들어온다.

### ❌ 알림 · 푸시

**금지.** 사용자가 명시적으로 배제했다.

- 할일 앱의 알림은 **잔소리**가 된다. 무시하기 시작하면 앱 전체의 신뢰가 깎인다
- PWA에서 푸시 권한을 요청하는 순간 서지호(S8)는 닫는다
- 권한 요청 팝업 자체를 띄우지 않는다

### ❌ 게임화 — 포인트 · 레벨 · 뱃지

**금지.** 사용자가 명시적으로 배제했다.

- "3분기 캠페인 보고서"에 250포인트를 주는 건 앱의 톤과 맞지 않는다
- 포인트는 **행동을 왜곡한다.** 쉬운 할일을 많이 만드는 쪽으로 기울게 됨

### ❌ 스트릭 (B1 미채택)

- 스트릭은 강력하지만 **끊기는 순간 앱을 버리게** 만든다. 하윤은 육아 중이라 반드시 끊긴다
- 지속형의 성취감은 **진행률("12/31일")**로 충분히 표현된다 (요구사항 F2-4)

### ❌ 튜토리얼 · 온보딩 오버레이

- 서지호에게 +1, 하윤에게 매일 -1 (Phase 2 P3 주의사항)
- 빈 상태 화면의 문장 하나로 대체한다 (P12)

### ❌ 샘플 할일 데이터

- 하윤이 첫날 지워야 한다. 기본 카테고리 3개만으로 성격은 충분히 전달된다 (P12)

### ❌ 완료 시 축하 메시지 · 색종이

- 하루에 여러 번 체크한다. **매번 축하받으면 세 번째부터 방해**다
- E3의 0.25초 색 번짐이 축하를 대신한다

## 4. 구현 우선순위

| 순위 | 장치 | 이유 | 예상 |
|---|---|---|---|
| 1 | **E1 한 줄 추가 바** | 이탈 1순위 직접 대응. 이게 없으면 앱의 존재 이유가 약함 | 반나절 |
| 2 | **E4 파스텔 팔레트** | 색 정의가 늦으면 전체 UI가 밀린다. Phase 5에서 확정 필요 | Phase 5 |
| 3 | **E3 체크 인터랙션** | 저비용 고효과 | 1~2시간 |
| 4 | **E5 밀린 할일** | 데이터 로직만 있으면 UI는 단순 | 2~3시간 |
| 5 | **E2 PWA** | 마지막에 얹어도 됨 | 1~2시간 |

**E1과 E4가 실패하면 나머지가 성공해도 앱은 실패한다.**
