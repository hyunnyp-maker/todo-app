## 1. 계획이 움직인 지점

가장 크게 달라진 것은 **7장 "범위 제외"에 넣었던 항목 다섯 개를 결국 만들었다**는 점이다.
빼기로 한 판단이 틀려서가 아니라, v1 골격이 예산보다 일찍 끝나 남은 시간을 여기에 썼다.

| 항목 | 01번의 계획 | v1 실제 | 왜 바뀌었나 |
|---|---|---|---|
| 규칙 기반 반복 | **제외** — 지속형(`daily`)의 날짜별 체크로 대체 | **구현** (매일 · 평일 · 매주 요일 · 매월 날짜) | "매주 월요일 회의"를 기간형으로 흉내 낼 방법이 없었다. 규칙 한 줄(`jsonb`)만 저장하고 뜨는 날은 조회 때 계산해, 우려했던 반복 엔진의 무게를 피했다 |
| 알림 | **제외** — 브라우저 상시 실행을 전제할 수 없음 | **구현** (정시 · 10분 전 · 1시간 전 · 하루 전) | 전제는 여전히 맞다. 그래서 "완전한 알림"을 만들지 않고, **한계를 UI에 그대로 적어** 켜는 사람이 알고 켜게 했다 (4.3) |
| 검색 | **제외** — 카테고리 색 구분이 핵심 | **구현** (제목 부분 일치) | 색은 **보고 있는 달** 안에서만 작동한다. 석 달 전 할일은 색으로 못 찾는다 |
| 내보내기 · 가져오기 | v2 후보 | **구현** (JSON 백업/복원) | 게스트 모드가 localStorage인 이상, 브라우저를 지우면 전부 사라진다. 게스트를 진짜 기능으로 쓰게 하려면 탈출구가 필요했다 |
| 다크 모드 | "여유 있으면 재검토" | **구현** (라이트 · 다크 · 시스템) | 색 토큰을 CSS 변수로 짜 둔 덕에 값만 한 벌 더 만들면 됐다 |
| 팔레트 | **파스텔** 9색 | **비비드 18색** + 대비 보정 토큰 | 파스텔은 채도가 낮아 색각 이상에서 구분이 어렵고(6.2에 스스로 적어둔 문제), 9색으로는 카테고리 10개째부터 색이 겹쳤다 |
| 음성 입력 | 항목 자체가 없음 | **구현** (음성 → 파싱 → 확인 → 저장) | "입력 마찰 제거"가 이 앱의 1번 목표(1.2)인데, 타이핑보다 마찰이 낮은 경로가 남아 있었다 |
| Google 로그인 | F0-4 | **제거** | OAuth 클라이언트 등록에 도메인 검증이 필요해 포트폴리오 배포 일정과 맞지 않았다. 이메일 + 게스트로 충분히 성립한다 |
| 스타일링 | "Phase 6에서 확정" | **Tailwind CSS v4 + CSS 변수** | |
| 배포 | "Vercel (예정)" | **Vercel** 확정 | |

**범위를 지킨 것** — 공유 · 다중 사용자 · 권한 · 충돌 병합 · 실시간 동기화 · 하위 체크리스트 ·
드래그 앤 드롭 · 주간/연간 뷰는 계획대로 v1에서 만들지 않았다.

## 2. 최종 데이터 모델

### 2.1 스키마

01번의 `categories` / `tasks`에서 **컬럼 세 개와 테이블 하나**가 늘었다.

```sql
-- 반복 · 알림 (0005)
alter table tasks
  add column recurrence    jsonb,                          -- null = 반복 없음
  add column reminder      text not null default 'none'
    check (reminder in ('none','at','10m','1h','1d')),
  add column reminder_time text not null default '09:00'
    check (reminder_time ~ '^([01][0-9]|2[0-3]):[0-5][0-9]$');

-- 반복 회차의 완료 기록
create table task_occurrences (
  task_id  uuid not null references tasks(id) on delete cascade,
  owner_id uuid not null default auth.uid() references auth.users(id) on delete cascade,
  date     date not null,
  primary key (task_id, date)          -- 같은 회차를 두 번 눌러도 행은 하나
);

-- 검색: ilike '%…%'는 인덱스를 타지 못한다
create index tasks_title_trgm_idx on tasks using gin (title gin_trgm_ops);

-- 복원: 전부 되거나 전부 안 되거나
create function restore_backup(payload jsonb) ... security invoker;
```

**설계 판단 세 가지**

1. **반복은 규칙만 저장한다.** '매일'을 1년치로 펼치면 한 사람이 365행을 쓰고,
   규칙을 고치면 그 365행을 다시 손봐야 한다. 뜨는 날은 조회 시점에 계산한다.
2. **완료 기록은 할일 본체와 분리한다.** 규칙을 바꿔도 지난 체크 이력이 살아남는다.
3. **복원은 서버 함수 한 트랜잭션.** 지우고 넣는 일을 클라이언트에서 나눠 하면
   중간에 끊겼을 때 데이터가 사라진 채 끝난다.

`recurrence`가 있는 할일도 `start_date` / `end_date`를 채워 둔다.
그래야 기존 범위 조회(`start_date <= :to and end_date >= :from`)가 그대로 통한다.

### 2.2 클라이언트 타입

```ts
type PaletteKey =
  | "red" | "orange" | "yellow" | "green" | "blue" | "pink" | "purple" | "brown" | "ink"
  | "lime" | "mint" | "sky" | "navy" | "indigo" | "wine" | "peach" | "khaki" | "gray";

type RecurrenceRule =
  | { type: "daily";    endDate?: ISODate }
  | { type: "weekdays"; endDate?: ISODate }
  | { type: "weekly";   daysOfWeek: number[]; endDate?: ISODate }   // 0=일 … 6=토
  | { type: "monthly";  dayOfMonth: number;   endDate?: ISODate };

type ReminderOffset = "none" | "at" | "10m" | "1h" | "1d";

interface Task {
  id: string;
  categoryId: string | null;        // null = 미분류
  title: string;
  memo?: string;
  startDate: ISODate;
  endDate: ISODate;
  checkMode: CheckMode;             // "once" | "daily"
  done: boolean;                    // once 전용
  completedDates: ISODate[];        // daily 전용
  recurrence: RecurrenceRule | null;
  reminder: ReminderOffset;
  reminderTime: string;             // "HH:MM"
  sortOrder: number;
  createdAt: string;
}

interface TaskCompletion { taskId: string; date: ISODate }   // 반복 회차 체크

interface GuestData {
  schemaVersion: 1;                 // 올리지 않는다 — 올리면 저장된 데이터를 못 읽는다
  categories: Category[];
  tasks: Task[];
  completions: TaskCompletion[];
  migrationAsked: boolean;
}
```

**완료 판정의 세 갈래** — 반복은 `checkMode`와 별개의 축이다.

| | 판정 |
|---|---|
| `once` | `done === true` |
| `daily` | 기간 내 모든 날짜가 `completedDates`에 있음 |
| 반복 있음 | `checkMode`를 보지 않고 `TaskCompletion` 기록으로 회차마다 판정 |

**팔레트 호환** — 새 색 이름은 예전에 쓰던 키(`sage` · `teal` · `mist` 등)와 겹치지 않게 골랐다.
저장된 옛 값이 조용히 다른 색으로 바뀌지 않고 기본색으로 정규화된다.

data/    storage(손상 복구) · merge(재시도 큐)
stores/  uiStore (달 이동 시 선택 날짜 동기화)

## 7. 이 문서의 갱신 규칙

**커밋할 때마다 이 문서를 함께 갱신한다.** 기능이 늘거나 스키마가 바뀌었는데
여기 반영되지 않으면, 다음 사람이 읽는 명세가 코드와 어긋난다.

| 바뀐 것 | 고칠 곳 |
|---|---|
| 기능 추가 · 제거 | 3장 기능 목록 (필요하면 1장에 판단 근거) |
| 스키마 · 타입 변경 | 2장 |
| 성능 · 접근성 · 테스트 수 | 4장 |
| 완료 기준 변동 | 5장 |
| v2 이월 항목 변동 | 6장 |
| 문서만 고친 커밋 | 갱신 불필요 |

머리말의 **기준 커밋 해시**도 함께 고친다.
[01 요구사항](./01-requirements.md)은 착수 전 기록이므로 **고치지 않는다.**
