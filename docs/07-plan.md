## 0. 왜 게스트 먼저인가

```
M1 ──▶ M2 ──▶ M3 ──▶ M4 ──▶ M5 ──┬──▶ M6 ──▶ M7 ──▶ M8
              │                   │
        여기서 이미           여기서 앱이
        화면이 돈다           기능적으로 완성
                            (게스트 모드 = 최종 기능)
```

- `TodoRepository` 인터페이스가 이미 설계돼 있어, Supabase는 **구현체 추가**로 끝난다
- 게스트 모드는 버리는 프로토타입이 아니라 **v1의 최종 기능**이다 (요구사항 3.1)
- 인증·OAuth 설정이 막혀도 **M5까지의 결과물은 그대로 살아 있다**

## M6 — Supabase 인증 + 저장소 (2.5h)

### 🔧 사용자가 직접 하실 준비 (시작 전)

이 단계에 도달하면 안내드립니다. 순서대로:

1. Supabase 프로젝트 생성 → **URL · anon key** 확보
2. Google Cloud Console → OAuth 클라이언트 ID 발급
   리디렉션 URI: `https://<project>.supabase.co/auth/v1/callback`
3. Supabase → Authentication → Providers → **Google** 에 ID/시크릿 입력
4. Supabase → Auth → URL Configuration 에 `http://localhost:3000` 등록

### 할 일

- `0001_init.sql` 실행 (테이블 · 인덱스 · **RLS** · 트리거)
- `@supabase/ssr` 클라이언트 (브라우저 · 서버)
- 로그인 · 가입 · 로그아웃 · 비밀번호 재설정
- Google OAuth + `/auth/callback` Route Handler
- `SupabaseRepository` + `mappers.ts` (snake_case ↔ camelCase)
- `useRepository` — 세션에 따라 저장소 교체
- TanStack Query 도입 (쿼리 키 · 낙관적 업데이트)

### 끝나면 보이는 것

로그인하면 데이터가 서버에 저장되고, 다른 브라우저에서도 보인다.

### 검증

- **수동 (⭐ 보안)**
  - **다른 계정으로 로그인 → 남의 데이터가 안 보인다** (RLS)
  - Supabase 대시보드에서 두 테이블 모두 RLS **enabled**
  - `git log -p | grep -i service_role` → 결과 없음
  - 로그아웃하면 게스트 모드로 돌아간다
- Google 로그인 · 비밀번호 재설정 메일 수신

## 4. 진행 방식

각 마일스톤은 이 순서를 지킨다.

```
① 구현 → ② 자동 테스트 + 수동 확인 안내 → ③ 결과 보고 (멈춤) → ④ OK 후 다음 M
```

- M1 시작 전에 **plan mode**로 실행 순서를 잡고 승인받는다
- 각 M이 끝나면 **브라우저에서 확인하실 포인트**를 알려드리고 멈춘다
- 수정 요청은 해당 M 안에서 처리하고 다시 확인받는다
