# 01. 요구사항 정의서

> 색으로 구분하는 다중 영역 할일 앱 — 달력 위에서 여러 날짜에 걸친 일정을 관리한다.

작성일: 2026-08-03
문서 위치: `D:\to do app\docs\`

---

## 1. 프로젝트 개요

### 1.1 한 줄 정의

> 개인이 **직장 / 개인 / 가족** 등 삶의 영역별로 할일을 나누고, 각 영역에 **파스텔 색상**을 지정해
> **월간 달력** 위에서 여러 날에 걸친 일정을 한눈에 파악하는 반응형 할일 앱.

### 1.2 목적

| 축 | 내용 |
|---|---|
| **1차 목적** | 포트폴리오 — 채용/외부 공유를 전제로 완성도와 디자인 품질을 갖춘다 |
| **2차 목적** | 실사용 — 만든 사람이 실제로 매일 쓸 수 있어야 한다 |

두 목적이 충돌할 때의 판단 기준:
- **보여주기용 화려함 < 실제로 손이 가는 편의성.** 실사용에서 거슬리는 기능은 포트폴리오에서도 티가 난다.
- 단, **첫인상 3초**(첫 화면의 밀도·색감·정렬)는 포트폴리오 쪽에 무게를 둔다.

### 1.3 주 사용자

개인 사용자 1명. 로그인·회원가입·다중 사용자 개념 없음.
데이터는 사용자의 브라우저에만 존재한다.

## 2. 기술 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| **디바이스** | **모바일 우선(Mobile First) 반응형** | 할일 확인·체크는 이동 중 휴대폰에서 가장 자주 일어난다. 모바일을 기본 설계로 잡고 데스크톱을 확장한다 |
| **프레임워크** | React 18 + TypeScript | 달력 셀 · 카드 · 필터의 컴포넌트 분리가 명확해짐 |
| **빌드 도구** | Vite | 설정 부담 없이 즉시 개발 시작, 빌드 산출물이 정적 파일이라 배포가 쉬움 |
| **저장 방식** | localStorage | 서버 없이 영속 저장. 개인 1인 사용 전제에 충분 |
| **스타일링** | (Phase 6에서 확정) | CSS Modules / Tailwind / vanilla-extract 중 선택 |

### 2.1 반응형 기준 — 모바일 우선

**기본(base) 스타일이 모바일**이고, 미디어 쿼리는 `min-width`로만 확장한다. `max-width`로 데스크톱 스타일을 되돌리는 방식은 쓰지 않는다.

| 구간 | 폭 | 레이아웃 |
|---|---|---|
| **모바일 (기준)** | 375 ~ 767px | 단일 컬럼. 달력이 화면 상단, 당일 리스트가 그 아래. 추가 버튼은 엄지가 닿는 하단 고정 |
| 태블릿 | 768 ~ 1023px | 달력 셀이 커지고 각 셀에 할일 제목이 직접 보임 |
| 데스크톱 | 1024px ~ | 달력과 리스트를 나란히 배치 (Phase 5에서 확정) |

**모바일 우선이 낳는 파생 결정**
- 달력 셀은 좁으므로 **점(dot) 또는 얇은 막대**로만 표현하고, 제목은 아래 리스트에서 읽는다
- 할일 추가는 화면 전환(모달·바텀시트)으로 처리한다 — 사이드 패널 방식은 모바일에서 성립하지 않음
- 카테고리 필터는 가로 스크롤 칩(chip) 형태를 기본으로 한다
- 터치 타깃 44×44px가 **기본값**이지 예외 처리가 아니다

## 3. 데이터 모델

### 3.1 Category (카테고리)

```ts
interface Category {
  id: string;        // uuid
  name: string;      // "직장", "개인", "가족" — 사용자가 수정 가능
  color: string;     // 파스텔 색상 hex. 사용자가 선택 가능
  order: number;     // 표시 순서
}
```

- 초기값으로 **직장 / 개인 / 가족** 3개를 제공한다.
- 사용자는 **추가 · 이름 수정 · 색상 변경 · 삭제**를 모두 할 수 있다.
- 카테고리 개수 상한: 없음. 단 UI는 6개 내외에서 가장 보기 좋게 설계한다.

**삭제 정책 (확정)**

카테고리는 **소속 할일이 있어도 삭제할 수 있다.** 삭제 자체를 막지 않는다.
다만 삭제 순간에 소속 할일을 어떻게 할지는 사용자가 고른다.

| 상황 | 동작 |
|---|---|
| 소속 할일 0개 | 확인 없이 바로 삭제 |
| 소속 할일 1개 이상 | 확인 다이얼로그에서 두 갈래 중 선택<br>① **할일은 "미분류"로 옮기고 카테고리만 삭제** (기본 선택)<br>② **할일까지 함께 삭제** (되돌릴 수 없음을 명시) |

`미분류`는 이름변경·삭제가 불가능한 시스템 카테고리다. 소속 할일이 0개면 UI에 노출하지 않는다.
마지막 남은 사용자 카테고리도 삭제할 수 있으며, 이 경우 화면은 "카테고리를 만들어주세요" 빈 상태가 된다.

### 3.2 Task (할일)

```ts
interface Task {
  id: string;
  title: string;
  categoryId: string;
  startDate: string;   // "YYYY-MM-DD"
  endDate: string;     // "YYYY-MM-DD" — 하루짜리면 startDate와 동일
  done: boolean;       // 기간 전체에 대한 단일 완료 상태
  memo?: string;
  createdAt: string;   // ISO 8601
  order: number;       // 같은 날짜 안에서의 정렬 순서
}
```

**핵심 설계 판단 — 기간형(B1-a) 채택**

할일은 `startDate ~ endDate` 기간을 가지며, **체크는 한 번만** 한다.
날짜별 개별 체크(반복형)나 하위 항목(묶음형)은 채택하지 않았다.

```
"이사 준비"   3/10 ▓▓▓▓▓▓▓▓▓▓▓▓▓ 3/16      → 체크 1회로 완료
```

파생 규칙:
- `endDate >= startDate` 를 항상 보장한다. 위반 입력은 저장 단계에서 막는다.
- 기간이 달을 넘어가면(예: 3/28 ~ 4/3) 양쪽 달의 달력에 모두 표시된다.
- 완료된 할일도 달력에서 사라지지 않고, **흐리게 처리 + 취소선**으로 남는다.

### 3.3 앱 전체 상태

```ts
interface AppState {
  categories: Category[];
  tasks: Task[];
  selectedDate: string;      // 당일 리스트가 보여줄 날짜
  visibleMonth: string;      // "YYYY-MM" — 달력이 보여주는 달
  hiddenCategoryIds: string[]; // 필터로 숨긴 카테고리
}
```

localStorage 키 1개에 위 구조를 JSON 직렬화해 저장한다. (스키마 버전 필드는 Phase 6에서 확정)

## 5. 비기능 요구사항

### 5.1 성능

- 할일 300개 기준으로 달력 전환·체크 토글이 체감 지연 없이 동작
- 초기 로딩 1초 이내 (로컬 환경)

### 5.2 접근성

- 모든 인터랙티브 요소에 키보드 접근 가능
- 체크박스·버튼에 적절한 label / aria 속성
- **색만으로 카테고리를 구분하지 않는다 (확정)** — 파스텔 배경은 채도가 낮아 색각 이상 사용자에게 구분이 어렵다. 할일 카드에 카테고리 **이름 텍스트를 항상 함께 노출**한다. 공간이 좁은 모바일에서도 이 텍스트는 생략하지 않는다
- 텍스트 대비: 파스텔 배경 위 본문 텍스트가 WCAG AA(4.5:1)를 만족하도록 색을 고른다

### 5.3 반응형 (모바일 우선)

- **375px(iPhone SE)를 설계 기준 폭으로 삼는다.** 데스크톱에서 잘 보이는 것을 모바일로 줄이는 게 아니라, 375px에서 완성한 뒤 넓은 화면으로 확장한다
- 모든 터치 타깃 최소 44×44px
- 어떤 폭에서도 가로 스크롤이 발생하지 않음
- 주요 조작(추가·체크·날짜 이동)이 한 손 엄지 범위 안에서 가능

### 5.4 한글 입력

- 한글 IME 조합 중 Enter가 중복 입력되지 않도록 처리 (`isComposing` 확인)

## 6. 범위 제외 (Out of Scope)

하루라는 시간 예산 안에서 완성도를 지키기 위해 **의도적으로 제외**한다.

| 제외 항목 | 이유 |
|---|---|
| 로그인 · 회원가입 · 다중 사용자 | 개인 1인 사용 전제 |
| 서버 · 원격 DB · 기기 간 동기화 | localStorage로 충분 |
| 반복 일정 (매일/매주 자동 생성) | B1에서 기간형만 채택 |
| 하위 체크리스트 (묶음형) | B1에서 기간형만 채택 |
| 알림 · 푸시 · 이메일 | 브라우저 상시 실행을 전제할 수 없음 |
| 드래그 앤 드롭 일정 이동 | 구현 비용 대비 우선순위 낮음. v2 후보 |
| 주간 뷰 · 연간 뷰 | 월간 뷰에 집중 |
| 검색 · 태그 · 우선순위 필드 | 카테고리 색 구분이 이 앱의 핵심 |
| 데이터 내보내기/가져오기 | v2 후보 |
| 다크 모드 | Phase 5에서 여유가 있으면 재검토 |

## 7. 완료 기준 (Definition of Done)

아래를 모두 만족하면 v1 완료로 본다.

**기능**
- [ ] 달력에서 월 이동이 되고, 오늘 날짜가 강조된다
- [ ] 여러 날에 걸친 할일이 달력에 막대로 이어져 표시된다
- [ ] 날짜를 클릭하면 아래 리스트가 해당 날짜로 바뀐다
- [ ] 할일을 추가·수정·삭제할 수 있다
- [ ] 체크하면 달력과 리스트 양쪽에 즉시 반영된다
- [ ] 카테고리를 추가·이름수정·색변경·삭제할 수 있다
- [ ] 소속 할일이 있는 카테고리도 삭제할 수 있고, "미분류로 이동 / 함께 삭제"를 고를 수 있다
- [ ] 카드 배경이 카테고리별 파스텔 색으로 칠해진다
- [ ] 카테고리 필터 토글이 달력과 리스트에 함께 적용된다
- [ ] 새로고침해도 모든 데이터와 필터 상태가 유지된다

**품질**
- [ ] 375px 폭에서 가로 스크롤 없이 모든 기능 사용 가능 (설계 기준 폭)
- [ ] 모든 할일 카드에 카테고리 이름 텍스트가 보인다 (모바일 포함)
- [ ] 한글 입력 시 Enter 중복 입력이 없다

- [ ] 할일 0개인 첫 실행 상태가 어색하지 않다
- [ ] `npm run build` 가 에러·경고 없이 통과한다

**포트폴리오**
- [ ] README에 스크린샷과 한 줄 소개가 있다
- [ ] 첫 화면이 비어 있어도 앱의 성격이 3초 안에 전달된다
