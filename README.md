# Myquence — 색으로 구분하는 달력 할일 앱

> 캘린더의 날짜 감각 + 할일 앱의 체크. 그런데 노션보다 가볍게.  
> _by hyunnyp_

**https://todo-app-two-jet-82.vercel.app** — 가입 없이 바로 써볼 수 있습니다.

직장 · 개인 · 가족처럼 하루에 뒤섞이는 영역을 파스텔 색으로 나누고,
월간 달력 위에서 여러 날에 걸친 할일까지 한 화면에서 관리합니다.

---

## 왜 만들었나

기존 도구에는 각각 빈 구멍이 있었습니다.

| 도구 | 불편함 |
|---|---|
| 캘린더 앱 | 일정은 되는데 **완료 개념이 없다**. 지난 주를 봐도 한 일인지 못 한 일인지 모른다 |
| 노션 · Todoist | 기능은 많은데 **열기가 무겁다**. 30초 안에 적어야 하는데 그 시간을 앱 여는 데 쓴다 |

그래서 **날짜 감각과 완료 체크를 한 화면에** 두고, 입력 마찰을 최대한 깎았습니다.

---

## 설계 원칙

기획 단계에서 실제 사용 시나리오를 먼저 쓰고, 거기서 원칙을 뽑았습니다. ([docs/](./docs))

- **입력은 3탭 · 3초** — 제목 외 모든 필드에 기본값이 채워져 있다
- **앱을 열면 항상 오늘** — 마지막 본 날짜를 기억하지 않는다
- **달력과 오늘 리스트가 한 화면에** — 375px 기준, 스크롤 없이
- **완료 항목은 사라지지 않는다** — "오늘 뭘 했지"에 답할 수 있어야 한다
- **색만으로 구분하지 않는다** — 카드에 카테고리 이름을 항상 함께 노출

가장 중요한 판단은 **이탈 원인이 성취감 부족이 아니라 입력 마찰**이라고 본 것입니다.
그래서 보상 장치(스트릭 · 포인트 · 뱃지)를 전부 버리고, 마찰 제거에 예산을 몰았습니다.

## 주요 기능

**한 줄 추가 바** — 하단 고정. Enter로 저장하고 커서가 유지돼 연속 입력이 됩니다.
날짜는 보고 있는 날짜, 카테고리는 마지막에 쓴 것이 기본값입니다.

**두 가지 체크 방식** — 하나의 데이터 모델로 둘을 표현합니다.

```
마감형(once)   "이사 준비"   3/10 ▓▓▓▓▓▓▓ 3/16   → 체크 한 번
지속형(daily)  "매일 걷기"   3/1☑ 3/2☑ 3/3☐ …    → 날짜마다 · 12/31일
```

**카테고리** — 추가 · 이름 수정 · 색 변경 · 삭제 · 드래그 재정렬.
색은 컬러 심리 차트에서 뽑은 비비드 9색 칩에서 고르고, 탭하는 즉시 카드와 달력에 반영됩니다.
소속 할일이 있어도 삭제할 수 있고, 그때 "미분류로 옮기기 / 함께 삭제"를 고릅니다.

**반복 일정** — 매일 · 평일 · 매주 특정 요일 · 매월 특정 날짜. 종료일은 선택입니다.
규칙 한 줄만 저장하고 날짜별 복제본은 만들지 않습니다 — 뜨는 날은 조회할 때 계산합니다.
체크는 회차마다 따로 남고(`task_occurrences`), 규칙을 고쳐도 지난 기록은 살아 있습니다.
수정은 전체 반복에 적용됩니다(단일 회차만 고치기는 v2).

**알림** — 기본은 꺼짐. 정시 · 10분 전 · 1시간 전 · 하루 전 중에서 고릅니다.
권한은 알림을 켜는 순간에만 요청합니다. 앱 시작 시 묻지 않습니다.

> **한계** — 웹 페이지의 알림은 앱이 열려 있는 동안만 예약·발송됩니다.
> 탭을 완전히 닫으면 울리지 않고, 다시 열었을 때 최근 2시간 안에 지나간 것까지만 되살립니다.
> 완전한 백그라운드 알림에는 Push API와 발송 서버가 필요하고, 그건 v1 범위 밖입니다.
> iOS Safari는 홈 화면에 추가한 PWA에서만 알림을 허용합니다.
> 이 내용은 알림을 켤 때 화면에도 그대로 나옵니다.

**음성으로 추가** — 마이크를 누르고 "내일 오후 3시 병원 예약"처럼 말하면
제목 · 날짜 · 시간 · 반복을 나눠 확인 화면에 올립니다. **자동 저장하지 않습니다** —
모든 칸을 고칠 수 있고, 저장을 누르기 전까지 아무것도 만들어지지 않습니다.

파싱은 규칙 기반입니다. 외부 AI API를 부르지 않아 말한 내용이 서버로 나가지 않고,
응답을 기다리지 않으며, 무거운 NLP 라이브러리도 넣지 않았습니다.
알아듣는 표현은 상대 날짜(오늘 · 내일 · 모레 · 다음 주 월요일 · 다음 달 10일),
절대 날짜(8월 10일 · 2026년 8월 10일 · ~까지 · ~부터 ~까지),
시간(오전 9시 · 오후 3시 · 14시 · 9시 30분 · 오후 3시 반),
반복(매일 · 평일마다 · 매주 월요일 · 매주 화요일과 목요일 · 매월 25일)입니다.

> **한계** — 브라우저마다 지원이 갈립니다. Chrome·Edge는 되고 Firefox는 되지 않습니다.
> iOS·Safari는 동작 방식이 달라 중간 결과가 보이지 않을 수 있습니다.
> 인식은 네트워크를 쓰므로 연결이 없으면 실패하며, 결과가 항상 정확하지도 않습니다.
> 그래서 저장 전 확인 화면이 필수입니다. 지원하지 않는 브라우저에서는
> 마이크 버튼이 꺼지고 안내가 뜨며, 손으로 입력하는 길은 그대로 열려 있습니다.
> 마이크 권한은 버튼을 누를 때만 요청합니다.

**검색** — 제목 부분 일치. 대소문자를 구분하지 않고 앞뒤 공백을 지웁니다.
일반 · 기간형 · 반복을 가리지 않으며, 보고 있는 달에 갇히지 않고 저장소 전체를 찾습니다.
검색을 닫으면 날짜 필터와 달력 선택이 그대로 돌아옵니다.

**백업 · 복원** — 설정에서 JSON 파일로 내보내고 가져옵니다.
카테고리 · 할일 · 반복 · 회차 완료 기록 · 화면 설정이 담기고,
비밀번호 · 토큰 · 세션은 담기지 않습니다.
가져오기는 병합이 아니라 **전체 교체**이며, 버전과 구조를 먼저 검증하고
무엇이 지워지는지 보여준 뒤 한 번 더 확인을 받습니다.
게스트는 단일 쓰기로, 로그인은 서버 함수 한 트랜잭션(`restore_backup`)으로 처리해
절반만 복원된 상태가 생기지 않습니다.

**밀린 할일** — 기본은 접힌 채 개수만. 날짜를 자동으로 바꾸지 않고,
`[오늘로]`를 눌렀을 때만 기간 길이를 유지한 채 옮깁니다.
반복 일정은 여기 들어가지 않습니다 — 어제 못 한 '매일 운동'은 밀린 것이 아닙니다.

**게스트 모드** — 로그인 없이 전 기능을 씁니다. 가입하면 이메일 계정 기준으로 저장돼
다른 기기에서도 이어집니다. 오프라인에서도 읽고 쓸 수 있고, 연결이 돌아오면 자동으로 맞춰집니다.

## 기술

| | |
|---|---|
| 프레임워크 | Next.js 16 (App Router) · React 19 · TypeScript |
| 백엔드 | Supabase (Postgres · Auth · RLS) |
| 서버 상태 | TanStack Query — 낙관적 업데이트 |
| UI 상태 | Zustand |
| 스타일 | Tailwind CSS v4 + CSS 변수 |
| 테스트 | Vitest (72개) |
| 배포 | Vercel |

### 구조

```
components  →  hooks  →  data  →  (Supabase / localStorage)
                 ↓
              domain            ← 순수 함수. 아무것도 import 하지 않는다
```

**`TodoRepository` 인터페이스 하나로 게스트와 로그인의 차이를 흡수합니다.**
컴포넌트는 자기가 어느 모드인지 끝까지 알지 못합니다.

`domain/`은 React도 Supabase도 모르는 순수 함수라, 테스트가 여기 집중돼 있습니다 —
월 그리드 · 기간 겹침 · 완료 판정 · 정렬 · 삭제 정책 · 손상 데이터 복구.

### 조회에서 신경 쓴 것

달력은 달이 아니라 **그리드 범위**(7/26 ~ 9/5)로 조회합니다.
단순히 시작일로 필터하면 3/28~4/3 할일이 4월 달력에서 통째로 사라집니다.

```sql
where start_date <= :to and end_date >= :from
```

RLS 정책은 `(select auth.uid())`로 감싸 쿼리당 한 번만 평가되게 했습니다.

## 로컬 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL · anon key 입력
npm run dev
```

환경변수 없이도 **게스트 모드로 전부 동작합니다.** 로그인 기능만 꺼집니다.

```bash
npm test        # Vitest
npm run build   # 프로덕션 빌드
```

DB 스키마는 [`supabase/migrations/`](./supabase/migrations)에 있습니다.
